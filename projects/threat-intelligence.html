Threat Intelligence & Detection Lab

A compact defensive workflow for IOC triage, CISA KEV collection, ATT&CK mapping and Splunk detection validation.

Code and detections included · live Splunk evidence pending

Project overview

A small analyst workflow for classifying submitted indicators, collecting the public CISA Known Exploited Vulnerabilities catalog, mapping behavior to MITRE ATT&CK and validating two defensive Splunk detections against synthetic authentication and proxy events.

Threat intelligenceIOC triageCISA KEVSplunk SPLMITRE ATT&CK

What is implemented

IOC triage CLINormalizes IP/domain inputs, detects documentation/private/test indicators, and labels confidence. It does not decide that a public address is malicious.
KEV collectorFetches CISA's public JSON catalog, filters by date/vendor/product and exports catalog metadata to CSV.
Detection contentSplunk searches for repeated authentication failures and repeated script-like or non-standard-port web egress, with ATT&CK context.

Run the IOC triage tool

python projects/threat-intelligence/scripts/ioc_triage.py projects/threat-intelligence/data/iocs.synthetic.csv --output projects/threat-intelligence/reports/ioc-triage.synthetic.csv

The sample IPs and domains are reserved documentation/test values. The utility uses local parsing only and does not submit indicators to third parties.

Collect current CISA KEV entries

Requires internet connectivity:

python projects/threat-intelligence/scripts/kev_watch.py --limit 25 --output projects/threat-intelligence/reports/kev-latest.csv
python projects/threat-intelligence/scripts/kev_watch.py --since 2026-01-01 --output projects/threat-intelligence/reports/kev-since-date.csv

Match catalog entries against your actual software and asset inventory before deciding that a vulnerability affects an environment.

Import the synthetic CSV files into a lab Splunk instance using sourcetypes portfolio:auth and portfolio:proxy. Replace index=main if your lab uses a different index. The SPL derives time from the timestamp field.

Evidence boundary

IOC and event fixtures are synthetic. The KEV collector performs a live fetch only when run. The SPL rules are authored content; Splunk execution screenshots and actual triage findings still need to be collected in the author's lab. User-agent strings and ports are weak signals by themselves and require analyst validation.
